# F122 实现设计

既有平台采用 React 路由、角色菜单和已登录用户 API。保留通用看板及个人默认面板，定制页面从独立菜单进入，读取公司看板 API。平台可配置菜单显隐，接口单独检查权限。

- 战略进展使用版本化台账。记录稳定编号和修订号，修改须带原修订号。组织与资产选项来自本租户现有资源。正式发布与知识验证的历史证据由获授权的管理员登记。
- 正式 Web 助手收到请求并进入处理后建立运行关联。观察器记录原始任务、实际子调用、主动区间和成果，将结果归到发生时的租户与使用部门。独立请求、调试和历史未采集区间分开。
- 只有成功根执行的最终回复与本人差评匹配时才进入问题清单。以首次差评归期，按截止日判断是否已办。写入处置记录时再次核验监控和处置权。首期明细只返回执行编号与措施。
- 北京时间选择统计期间。运行观测及评价时间按 UTC 落库。资产目录显示本机当前可核验的资料，历史发布不能由当前配置反推。
- 成果登记只接受本轮解释器实际发布的文件回执。显式登记的普通文件按存储对象去重，中间文件也可单件登记。编程产物按租户内的项目编号、显式版本及成员清单登记，未归集的代码文件保留为候选。同一文件先作为单件产出、后来归入版本时，早于归集时刻的报表仍计该文件，后续报表按版本计件。不同任务再次输出同一文件，也沿用这个归属。
- 约束取自 [架构约定](../../../docs/constitution.md)。接口以 /api/v1/company-boards 为根，核心读入口为 access、overview、ledger、feedback。写入 ledger 须有台账权限，写入 feedback/{run_id}/resolution 须有处置权。
