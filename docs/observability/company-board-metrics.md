# 公司看板数据采集与指标口径

适用于公司领导看板 `/leadboard` 的战略进展、业务赋能、应用活力，以及运营监控看板 `/monitorboard`。查询一个数字时，先确定它回答的是“计划建设多少”“已经上线多少”还是“实际执行多少”。同一工作流可以同时出现在场景计划和上线目录中，只有接入运行采集的入口才能提供它的使用次数、用户数和工时。

## 一、数据如何进入看板

逐项复核时打开[公司看板指标数据字典（Excel）](公司看板指标数据字典.xlsx)。按页面入口或界面名称筛选，可查到每个数字、图表系列、状态和下钻字段的业务来源、原表字段、接口、计算规则及验收样例。公司建设与经营明细收在“业务赋能与科研”，从多个看板进入的单个资产和部门详情收在“资产与部门下钻”。“跨页验收”列出从台账填报、资产发布到评价处置的业务操作与预期。测试时先保存基线，再用相同租户、年月和筛选条件核对增量。

| 业务动作 | 写入或读取位置 | 看板用途 |
| --- | --- | --- |
| 管理员维护建设计划、专题、场景、承建和支持单位，填报知识接入目标或科研经营月报 | `company_board_ledger` 保存年度目标、专题、场景等主体及修订。 `board_supplement` 按类型和父记录保存分类计划、场景关联、专题案例、资产归属、月报与课题等 | 计划分母、关联维度、投产日期、直报累计值 |
| 资产创建、编辑、发布、下线 | 资产业务表提供查询时的目录。首次正式发布的证据投影为台账 `release` 记录。专题和知识分类归属另有生效记录 | 当前存量、当年建成、月新增、分类接入进展、部门贡献 |
| 用户发起一轮正式 Web 助手对话，模型、工具和知识库实际执行 | 助手创建一次运行观察对象，同一 `run_id` 下的终态及子事件批量写入 `board_runtime_event` | 成功任务、调用次数、使用部门、有效工时、Token、交付物、健康度 |
| 用户评价回复，管理员处理问题 | `board_web_rating` 留存评价变化，`board_issue_resolution` 保存问题处理记录，通过终态消息及运行关联 | 好评率、负反馈问题、处理情况 |

运行事件有共用事实表。目标、资产目录、反馈和业务报表各有来源。一次业务请求可以产生一条数字员工终态、两条工具调用、一条知识检索和若干模型调用。看板分别从这些记录计算任务量、资产调用量和 Token；这三个数没有相互相等的要求。[看板模型](../../src/backend/bisheng/company_board/domain/models/) · [总览查询与权限](../../src/backend/bisheng/company_board/domain/services/boards.py)

**时间范围。** 报表按北京时间划日、月、年，已结束月份截至月末，在途月份截至查询时刻。运行事实以 UTC 存储，查询区间含起点、不含终点。跨月的工具调用与数字员工终态可落在不同月，近 90 天含截止日在内。

**部门范围。** 领导看板、监控看板和填报台账统一使用当前租户“葛洲坝供应链公司”的有效直属单位。资产首发、用户运行、场景承建和支持等记录保留各自的原始部门，读报表时沿当前有效组织树向上归入直属单位。例如，集中采购中心下两个业务组分别使用 2 次和 3 次，部门排行和下钻均归入集中采购中心，合计 5 次。按部门数统计时该中心计 1 个。公司本级、树外单位以及无法对应有效直属单位的记录不参与部门排行、部门筛选或部门数；无部门筛选的公司指标按原有业务事实统计，可能大于各部门合计。找不到唯一的有效公司节点时，部门列表为空。组织调整可改变历史记录在部门报表中的归属。[部门归集规则](../../src/backend/bisheng/company_board/domain/repositories/planning_departments.py)

**部门所代表的业务关系。** 资产贡献取首次发布的归属部门，优先沿用同年旧计划的部门，否则取上线时资产所有人的未删除主部门，多条时取部门 ID 最小的一条。运行使用取请求发起人当时唯一的未删除主部门。场景承建和支持单位从直属单位中选取，按承建、支持分别统计；历史支持单位归入同一直属单位时只列一次，和承建单位重复时只列承建。监控按资产归属部门筛选，使用排行按使用者所属部门统计。[运行记录](../../src/backend/bisheng/company_board/domain/repositories/runtime.py) · [年度与近 90 天查询](../../src/backend/bisheng/company_board/domain/services/activity_trends.py)

## 二、战略进展

| 页面元素 | 分子、分母及下钻依据 |
| --- | --- |
| 年度数字员工建设计划、月度新增、年度完成率 | 分母取当年数字员工目标。分子取截止日以内、本年有效上线的助手、工作流、托管应用的不同资产键；关联场景的上线记录须属于有效专题下的计划场景。月柱按上线日期所属月，点击可核对资产及日期。完成率为建成数除以目标，缺目标或分母为零时无法给出比例。 |
| 业务知识接入、分类进度 | 管理员按年度维护业务分类、计划数和计划完成日。首页总数包含全部分类。进度条只列计划数大于零且完成率最高的四类，按完成数除以计划数排序，同率按完成数降序、再按中文名称排序。点击“业务知识接入”可核对全部分类的计划数、已接入数和计划完成日期。创建或编辑普通知识库、问答库时，从已有分类中选择。某库首次获得分类的年份决定接入年度；同年换分类将这一份完成量移至新分类，清空分类则退出。按截止日将当年首归类、仍存在的库归入对应的计划分类。到达计划完成日本身不会增加完成量。旧版已核验且可关联现有库的记录兼容读取。具有访问限制的库也可能贡献分类合计。 |
| 业务场景 · 年度计划已投产 | 分母取年度场景目标。分子是本年度有效专题下、投产日期落在当年且不晚于截止日的不同场景数；同一场景关联三个资产仍计一个场景。下钻核对专题、场景和投产日期。 |
| 业务场景 · 本年使用次数、服务用户数 | 取截止日场景关联的数字员工并集，查询年初至截止日的成功运行。使用次数按成功运行计数，服务用户数按租户内用户跨员工去重。甲用员工 A 三次、员工 B 一次，两员工均关联场景，则公司合计 4 次、1 人。共用员工只算一次，可在明细中看到其多个场景。该指标衡量关联数字员工的服务量，关联可事后维护，执行无需选择场景，也不要求执行当天已投产。 |
| 公司 AI 资产概况、资产台账 | 查询时目录中，数字员工包括在线未删除助手、在线工作流、在线托管应用。知识库需已发布、非私有类型且公开。Skill 需启用且属公共所有者。工具/MCP 按有效工具集中的未删除工具项逐项计数。一个 MCP 服务提供四个有效工具即计四项。MCP 工具有展示标题时，目录优先使用协议的 title，其次使用 annotations.title，缺省时显示调用名。下钻按带类型前缀的资产键查看。 |
| 重点建设专题、代表案例 | 有台账维护权限的管理员通过五角星设置年度重点。首页一次展示一个已标星专题，可前后切换。取消标星后该专题仍可用于资产归属和场景计划。删除专题会保存逻辑删除记录，其资产转入默认专题；已有场景须先迁移，默认专题保留。资产可直接归属专题，默认“AI先锋行动”；场景可在场景管理中软关联多个资产。专题汇总依页面合并直接归属及场景关系，按资产键去重。“已发布资产”取其中仍在目录的资产，“贡献部门”为这些资产有发布部门的不同部门数。专题案例由管理人在专题管理中选该专题已上线的一位数字员工，展示其名称、说明并可进入相应资产。显式清空、新选资产不可用时，均优先采用此次选择的状态。 |
| 贡献与使用 | “部门资产沉淀”按本年度首次上线记录中的发布部门汇总，未知部门不进该排行。“数字员工使用”按所选总览期间、当前目录可见员工的成功运行次数排名。查看榜单应同时核对期间和归属维度。 |

新场景使用场景管理中的资产清单。已有显式清单（包括主动清空）优先；历史数据还可来自投产记录、有效的旧场景关联或旧案例。**经典场景排行**另外要求执行当天场景已投产且可唯一归属，近 90 天有成功运行、可计算好评率且达到 90%。一位员工同时服务两个已投产场景时，此运行可进入公司服务量，不能同时成为两个经典场景的业绩。[场景关联与服务量](../../src/backend/bisheng/company_board/domain/services/scene_usage.py) · [分类进度](../../src/backend/bisheng/company_board/domain/services/knowledge_progress.py) · [发布证据](../../src/backend/bisheng/company_board/domain/repositories/publication.py) · [目录筛选](../../src/backend/bisheng/company_board/domain/repositories/catalog.py) · [专题案例](../../src/backend/bisheng/company_board/domain/services/representatives.py) · [战略页面](../../src/frontend/platform/src/pages/CompanyBoards/prototype/Strategy.tsx)

**年度总数与首发明细。** 年度“已建成数字员工”按资产键去重，发布记录挂在场景下时还要校验所属场景及专题。月柱和年度首发明细直接按符合日期和类型的登记行统计。历史台账若重复登记或引用失效场景，应按资产键和父场景对账。首发明细的专题列通过发布登记关联的场景取得，仅为资产设置所属专题时该列可能为空。

## 三、运行采集与覆盖范围

| 事件 | 采集时点和识别条件 | 使用口径 |
| --- | --- | --- |
| 数字员工 `employee` | 已登录的 Web 助手聊天入口注入观察器，有已建立的会话 ID 时按一轮请求创建运行。终态记录资产、用户、部门、结果、开始及结束时间，可关联输入及最终回复消息 | 成功、失败、取消分别记录。任务完成数和数字员工使用次数只计成功。执行成功率分母为成功加失败。 |
| 知识库 `knowledge` | 观察器内执行带有可识别知识库 ID 的检索，正常返回记成功，抛错记失败 | 一次成功检索计一次使用；返回空结果仍可能正常完成。业务分类接入和实际检索分别统计。 |
| 工具/MCP `tool` | 工具执行器完成调用时结合异常和可识别错误回执判定，包括 MCP 错误标记及代码执行失败状态 | 成功进入使用次数，失败进入健康度。单纯以文本描述错误而没有异常或协议错误标记，存在被按正常返回统计的可能。 |
| Skill `skill` | 助手实际加载 Skill 时登记 `entered`，同一操作标识防止重放重复计数 | 调用进入次数。仅在配置中挂载、展示、搜索均不形成次数。Skill 目前没有与工具同口径的成功率。 |
| 模型 `model` | 模型结束回调提供有效的非负整数输入、输出 Token，记录该次模型调用的两项原始计量 | Token 为输入加输出，再按调用累加。一轮任务可调用模型多次。未上报用量的调用没有可加总计量，仅有部分回执时合计也是已知部分。 |
| 文件 `file`、版本 `version`、成员 `version_member` | 识别代码解释器本轮实际生成的文件链接；文档任务的受支持文档格式可自动登记，其他交付按实际返回链接登记。编程交付登记稳定项目标识、版本号和成员文件 | 三个独立登记文件计三件，包括已登记的中间成果。多个代码文件合为一个已登记版本则计一件。同租户同对象或同项目版本重放去重；截止日前已并入版本的文件不再独立计。无从确认旧版本成员时，相应文件数、交付物总数显示缺数。 |

**工时。** 从观察器开始到结束，扣除只有工具在执行、系统等待工具返回的区间。并行工具等待不重复扣时，等待期间仍有模型计算则保留该段时间。可闭合计时的成功和失败任务都计入总工时；取消任务单列。回调缺失、起止不配对等导致该任务工时未知，仍可计入成功或失败次数。已观测任务的工时计量覆盖率（`observed_timing_coverage`）为有有效计时的成功或失败任务数除以已观测的成功或失败任务数。全入口的任务分母未知，全量覆盖率（`timing_coverage`）为空。[采集器、计时和文件登记](../../src/backend/bisheng/common/board_observation.py) · [Skill 加载](../../src/backend/bisheng/api/services/assistant_skills.py) · [工具执行](../../src/backend/bisheng/tool/domain/services/executor.py) · [落库与汇总](../../src/backend/bisheng/company_board/domain/services/runtime.py)

**执行入口的覆盖差异。** 正式 Web 助手的接入点在助手 WebSocket 和聊天客户端。有会话但从其他入口调用同一个助手，并不自动继承这个观察器。Web 工作流对话、开放 API 的助手对话及工作流执行、托管应用自身的运行路径未在这里注入同一采集器。可在同租户分别从 Web 助手、Web 工作流和开放 API 调用，对比终态记录。本次隔离回放有三个已上线数字员工，其中两个助手有运行事实，工作流执行成功后仍显示未监测。历史目录中缺少首次正式发布时间时，资产仍可列为当前在用资产，不能据其创建时间补算当月新增。仪表中无记录的运行还应核对采集日志；本地 SQLite 拒绝写入实验中，用户收到了正常答复，事实表没有该轮终态。恢复写入后新请求能计数，先前失败的记录没有自动补采。排查此类缺口需同时核对聊天记录和服务端写入错误。[助手入口](../../src/backend/bisheng/api/v1/assistant.py) · [聊天客户端](../../src/backend/bisheng/common/chat/client.py) · [聊天管理器](../../src/backend/bisheng/common/chat/manager.py) · [Web 工作流入口](../../src/backend/bisheng/api/v1/workflow.py) · [开放 API 入口](../../src/backend/bisheng/open_endpoints/api/endpoints/)

## 四、业务赋能与应用活力

| 页面元素 | 计算、期间与可核查的明细 |
| --- | --- |
| 业务赋能 · 完成任务数、作业工时、年度交付物 | 成功运行数、已计量有效秒数之和除以 3600、去重文件加版本数。年度指标从年初累计至所选截止日，可下钻月度趋势、资产和交付类型（文档、图片、前端页面、其他及未分类）。失败任务可贡献工时，已产生的交付物有独立事件。 |
| 好评率、对话轮次 | 好评率 =（成功任务数 − 截止时最终为负评的成功任务数）÷ 成功任务数。只有成功数大于零且所有成功任务都能关联终态消息时才给出百分比。已关联且未评价的成功任务也计入分子，因此它不等同于主动评价者中点赞的比例。对话轮次按有终态消息的成功或失败运行计。 |
| 使用分布、专题运行 | 气泡按所选专题下数字员工本月已观测成功次数绘制。固定图幅内，使用最多的员工占最大圆，其他员工按各自次数与最大次数之比换算圆面积，极小值保留最小可见尺寸。专题明细关联员工、场景、运行状态和评价；跨场景榜单的归属规则见第二节。 |
| 科研与经营、课题与工作量估值 | 管理员按月直报当年累计值，读所选月底前同年最新报表，并显示来源月份；不能将相邻月份累计值相加。指标含年度实施科研项目数、其中 AI 项目数、当前在研 AI 项目数、在研 AI 项目全周期预算、年度 AI 经费净支出、合同本年度待收款、估值场景数、预计年度等效人工价值、预计年度直接费用节约、交付物等效人工工作量和折算人工产值。金额单位为万元。预估年度 AI 产值取两项年度预计值之和，项目及课题的 AI 占比分别取各自 AI 数除以总数。课题保存名称、所属项目、是否 AI、起止日等明细，可延续上年未结题记录。没有当年直报时按兼容规则读取已有台账明细；新填报只维护看板数值和课题。 |
| 等效工时、估算价值 | 有当年直报则使用填报的累计工作日和价值，按 8 小时折算一个工作日。兼容估算按交付物形成日、类别和单位（文件或版本）匹配当时最新有效费率；折算工时为数量乘以单位工时，价值再乘小时价格。缺费率或同日费率不唯一时不出估值。实际运行工时单独来自计时器。 |
| 应用活力 · 资产总量、构成、月度新增 | 同查询当月使用当前四类目录；浏览历史月份而缺历史目录时显示缺采。月新增按首次正式上线日期归月，页面明细还与现有目录匹配；下线或删除后，当前目录和可下钻明细可能变化。 |
| 资产使用次数、趋势、排行 | 数字员工、知识库、工具计成功调用，Skill 计实际进入。四类相加得到“资产使用次数”，一轮任务可贡献多次。趋势接口按整数传递各项次数，页面按数值相加。历史趋势按事件发生月汇总；排行和详情可按月份、近 90 天、部门、专题等页面支持的范围查看。数字员工健康度按同月成功率分级。 |
| 部门贡献与使用、Token | 部门新增看首次发布部门；使用量和 Token 看运行开始时记录的使用者主部门。月度 Token、年度 Token 与明细使用同一模型调用事实，页面按百万或亿换算。无用量回执不能解释为零消耗。 |

**场景计划、场景关联和实际执行分别取证。** 业务赋能专题台账的“年度计划资产”读取场景下的发布登记。管理员后补关联资产，会改变场景的关联清单和战略页服务量的取数范围。业务赋能的单场景执行量另查运行当天是否已经投产、能否唯一归属。对一名关联两个已投产场景的员工，只需发起一次成功请求，即可分别核对这三个口径。

## 五、运营监控与反馈

监控范围是筛选后的当前数字员工、知识库、工具/MCP 目录。专题、场景、资产发布归属部门、类型会改变范围，Skill 未纳入健康度分母。执行量、失败量和日趋势来自这些类型的终态，一个助手及其调用的工具可分别贡献一次执行。期间成功率为成功数除以成功加失败，取消不在该分母。

| 资产状态或入口 | 判定和核对方法 |
| --- | --- |
| 数字员工健康度 | 当月成功率 ≥98% 为正常，≥95% 且 <98% 为关注，<95% 为异常。 |
| 知识库、工具健康度 | 当月失败率 >5% 为异常，≤5% 为正常。 |
| 暂无执行、未监测、监测覆盖率 | 截止时有已观测终态，但当月成功加失败为零，显示“暂无执行”。截止时从未记录过终态则为“未监测”。覆盖率为范围内已监测资产数除以范围内资产数。仅配置了工具或上线了资产不能证明运行已被监测。 |
| 趋势和排行 | 按运行事件日期画趋势。异常列表按失败数及失败率等排序；正向列表从有成功记录的正常资产中选择。可下钻查看指标、执行记录和所属筛选范围。 |
| 负反馈及处理 | 对同租户、同用户的成功运行终态消息，第一次负面评价按运行生成一个问题，问题流入按首次负评日期归月。改评可改变好评率，但不会自动处理已形成的问题。处理记录包含措施、操作人、处理时间；有处置权限的账号才能处理和查看受限明细。 |

看板读取按当前租户和菜单授权。系统管理员具备看板管理权，其他账号分别授权领导、监控菜单；维护台账须同时有监控和台账权限，处理反馈须同时有监控和反馈权限。公司汇总不存储对话正文，查看具体问题、运行或消息内容另受明细权限及消息归属约束。[监控查询](../../src/backend/bisheng/company_board/domain/repositories/monitoring.py) · [状态分级](../../src/frontend/platform/src/pages/CompanyBoards/prototype/MonitorParts.tsx) · [评价和处理](../../src/backend/bisheng/company_board/domain/repositories/feedback.py)

监控中，仅有取消记录也能证明资产已接入监测；取消不会增加当月成功、失败或已结束运行数。正向榜混选类型时每类取第一，单选类型时取前五。反馈按首次负评月份归入；回看该月时按当月底的处置状态展示，次月处理不会把上月月底的待处理问题改成已处理。

## 六、复核与维护

页面新增数据、采集入口变更或统计口径调整时，同时更新本说明与 Excel 中对应的记录和验收样例。实际执行结果写入业务入口验收记录，并注明日期、环境、筛选条件和证据。

1. **确认查询上下文。** 在浏览器网络面板核对 `/api/v1/company-boards/` 下的 `overview`、`trends` 和 `monitoring` 响应。记下页面、年月、租户、资产键（如 `assistant:42`）、场景与部门筛选。战略建设累计、所选月运行、当前目录和近 90 天排行榜使用的时间窗口不同。
2. **从真实入口查到明细。** 对一轮已知请求，先用助手和终态消息定位 `employee` 事件，再按同租户、同 `run_id` 查看工具、知识、Skill、模型和文件事件。终态存在而某类子事件不存在，检查该回调、协议字段或交付登记；整轮无记录，检查发起入口、会话 ID、持久化错误和查询时间窗。
3. **核对汇总与归属。** 优先比对相同租户、期间、类型、状态的明细；人数须以用户 ID 跨员工去重。运行部门为空时核查请求发生时的主部门。发布部门、场景承建和支持单位不能补作运行使用部门。
4. **复查历史变化。** 已有运行事件保存原始时间和当时使用部门。目录按当前业务表读取；分类变更、场景重新关联、修订月报和删除源对象都可能改变相应历史页面或明细范围。没有历史发布证据、完整计时或可匹配用量时保留缺数；有证据表明特定范围成功次数为零时可显示零。
5. **新增指标或采集入口时。** 同步修改这份文档里对应的业务动作、事件粒度、唯一键、期间、权限与未覆盖范围。在真实入口重放成功、失败、重复和缺失证据样例，并对照事实表、汇总接口、页面下钻三处。[采集链路验证记录](../../features/v3.0.2/122-company-boards/collection-verification.md)提供本地样本、复跑方式和已知缺口。使用三个本地组织账号，从建库、发布、工作台对话一直核对到评价处置的步骤见[业务入口验收](../../features/v3.0.2/122-company-boards/live-business-acceptance.md)。查询与口径回归用例分列在[公司看板测试目录](../../src/backend/test/company_board/)。
