# 助手绑定技能与 Word 下载 · 本地验收记录

2026-11-25 在 `digitalemployeeplatform-dev-sync` 的 `feat/assistant-workbench-chat` 上验证。研发基线为 `cbe48a77f`，包含此前的多步过程展示、引用及历史回放修复。测试对象为该基线叠加本次提交的代码。本地构建端在 3001 端口，API 在 7860 端口。本地数据库已应用可空的 `assistant.skill_ids` 迁移，旧助手可继续使用原有工具和知识库配置。

## 原因与改动

助手的“工具与技能”原来只加载内置工具、API 工具和 MCP。编排代码里旧称“技能”的 `flow_list` 引用工作流，管理端的 Word、Excel、PPT、网页报告存放在独立的技能目录。助手缺少该目录的选项、绑定字段和运行时加载逻辑。

修复后选择器使用当前账号可用的技能目录。保存时校验新绑定，运行时按实际使用者重新筛选。技能读取工具向模型提供所选版本的说明和参考资料。内置文档和报告技能可使用有权限的代码执行器，以工作区内的技能脚本生成文件。助手技能产出的文件通过平台文件代理下载。Function calling 和 ReAct 共用该工具注册逻辑。

## 改动模块

| 模块 | 变更 |
| --- | --- |
| 构建端助手编排、工具抽屉 | 加入可搜索的技能目录，回显已绑定技能，支持添加、移除及查看说明。 |

| 回归测试 | 覆盖绑定与移除语义、运行时授权、ReAct 读取、执行器文件同步和下载，以及已有的对话与引用功能。 |

## 最短复验路径

1. 在待验环境使用有助手编辑权、Word 技能和代码执行器使用权的账号，创建未上线的助手并配置可用模型，确保企业目录已启用 Word 技能。入口为「构建 → 应用 → 助手 → 助手编排」。本地实测账号为 stafen，样例名称为“技能验收草稿 1125”。
2. 展开“工具与技能”，点加号，选“技能”，搜索“Word 文档制作”，新助手点击“添加”，保存后刷新应回显名称，再次进入选择器应显示“已添加”。移除、保存并刷新后应消失。
3. 在“调试预览”输入“请用 Word 技能生成可下载的 Word 验收纪要，标题为‘助手技能验收’，正文写‘本次检查了技能选择和文件生成’，含两行验收表格。请返回实际下载链接。”
4. 展开思考记录，查看读取技能、执行代码的步骤及详情。点击回答中的文件链接，打开 Word，核对标题、正文、表格。

## 自动化与覆盖范围

前端执行助手编排页签、聊天错误、运行日志收尾和模板回归。后端执行技能绑定、账号权限、撤权、旧配置兼容、输出文件代理、知识库鉴权、停止生成、工具历史、引用及代码执行器回归。ReAct 用可重复的模型响应驱动真实执行图，验证选中技能的内容返回给循环。E2B 文件同步使用模拟沙箱。[前端结果](frontend-tests.txt) · [后端结果](backend-tests.txt)

真实模型和浏览器端到端覆盖本地 Word 路径。Excel、PPT、网页报告验证了可选项；三种文件的生成、真实 E2B 服务、普通账号双人权限验收及公司测试环境尚未实测。业务方已确认本地功能验证结果。本报告记录开发自测，公司测试环境验收和发布另行进行。

## 技能选择器布局与构建入口复验

2026-11-25，沿用上述本地分支及测试账号。在 698 × 761 的助手编排页打开「工具与技能 → 技能」，选择器与管理页共用技能表格行和导入、新建按钮。表格内容宽度与容器宽度均为 488 像素。搜索「Excel 表格制作」能定位一行，点击名称能查看完整描述，点击添加后显示禁用的「已添加」。已有的 Word 绑定也显示为已添加。
