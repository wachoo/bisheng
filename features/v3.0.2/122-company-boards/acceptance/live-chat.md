# 工作台对话、调用和反馈验收

现行采购助手绑定问答库和报价工具。每轮复验从聊天历史读取知识检索与报价工具的结束回执，将输出与看板增量对照。供应商正常报价时，预期知识成功、工具成功和员工成功各增加 1 次。供应商拒绝时，预期知识成功、工具失败和员工成功各增加 1 次。公共 Skill 的发布在资产目录独立核验。[资产发布验收](live-assets.md)

## 复跑

先完成当期场景及资产关联，并给测试账号授予对应资源的使用权限。使用由浏览器登录取得的 Playwright storageState，在项目根目录运行。变量 `BOARD_ADMIN_SESSION` 指向管理员会话，`BOARD_SESSION` 指向当前操作者会话。凭据文件保存在仓库外。每次发起对话都会创建新业务记录，评价或处置使用该次输出的消息、会话及运行 ID。

1. 在本地 Compose 内部网络运行当前版本的 [live-chat-model.py](live-chat-model.py)，容器 DNS 名为 `board1126-test-model`，监听 8000。使用旧版本的容器需先加载新脚本，再执行对话任务。执行 `node <验收目录>/live-chat-provider.cjs`，注册或复用「采购协同推演服务」的 `board-live-chat` 模型，加入助手可选列表。物资采购比价助手选择输出的模型 ID，项目合同履约助手使用业务模型。
2. 从工作台日常聊天调用模型。下方 PowerShell 示例中的目录和 ID 按当前环境替换。脚本保存的回执包含预期、实际增量与逐项判定。QA 答案缺失时会返回非零退出码，该次操作仍会留下记录。

```powershell
$acceptance = 'features/v3.0.2/122-company-boards/acceptance'
$chatScript = Join-Path $acceptance 'live-chat.cjs'
$env:BOARD_CHAT_EVIDENCE = Join-Path $env:TEMP 'board-live-chat.jsonl'
node $chatScript daily 1
```

3. 切换 `BOARD_SESSION` 到相应用户，设置 `BOARD_EXPECTED_DEPARTMENT` 为该用户主部门 ID。通过工作台应用使用同一数字员工。

```powershell
node $chatScript assistant <采购助手ID> tools
node $chatScript assistant <采购助手ID> reject
node $chatScript assistant <履约助手ID> plain
```

4. 原操作者评价自己的消息，随后切换为管理员处置。处置提交后脚本会等待监控读数更新。核对已有处置用 `verify-resolution`，它只读结果。

```powershell
node $chatScript rate <消息ID> 1 <助手ID> <会话ID>
node $chatScript rate <消息ID> 2 <助手ID> <会话ID>
node $chatScript resolve <差评对应的运行ID>
node $chatScript verify-resolution <差评对应的运行ID>
```
